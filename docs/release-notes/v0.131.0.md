# PGRAC v0.131.0 — undo-header locality and UPDATE diagnostics

Author: SqlRush <sqlrush@gmail.com>

Release line: 2026-09-20. PostgreSQL base: 16.13. Distribution: source.

This version improves undo-header resource locality within the existing MVP
scope and includes correctness fixes encountered during qualification.
The [GitHub Release](https://github.com/sqlrush/pgrac/releases/tag/v0.131.0)
provides the final correctness results, immutable source identity and exact-commit
CI evidence. A version file or unpublished tag alone is not a qualification result.

## Changes

- Prefer the owning instance for initial undo-header resource placement, while
  retaining the existing resource directory, lock checks and remastering rules.
- Correct optional pre-assertion capture and retry shared-image registration
  after an exact, recoverable ownership conflict.
- Keep voting-record freshness bound to the selected instance identity during
  clean cluster startup.
- Resolve an old foreign transaction before interpreting a reused transaction
  slot's current local owner.
- Renew unchanged, unexpired write-fence authority without briefly publishing
  an unavailable lease. Changed identities, expiration and self-fencing retain
  their rejection behavior.
- Add opt-in, bounded UPDATE phase/event tracing and offline client-to-server
  latency attribution. Tracing is **off by default**; see the
  [tracing guide](../user-guide/update-tracing.md).

No disk-format, wire-format, benchmark-workload or configured-timeout change
is included. No extra service workers or transaction slots are enabled.
This is not a mixed-version or rolling-upgrade release.

## Controlled performance observations

An alternating control/candidate/candidate/control comparison used identical
normally stopped cold data, four instances with 32 clients each, a 5-second
warmup and a 35-second point-update measurement. Both builds contained the same
correctness fixes and tracing support, with tracing disabled. Only the
undo-header locality improvement differed. All four comparison runs passed
client/server error checks, full-row comparisons, health/debt checks and normal
shutdown.

| Run | Build | Cluster committed TPS |
|---|---|---:|
| 1 | Common corrected control | 212.86 |
| 2 | Locality candidate | 1423.09 |
| 3 | Same locality candidate | 1391.29 |
| 4 | Common corrected control | 879.03 |

The candidate mean was **1407.19 TPS**, about **60.1% above the faster control
run**. The control varied substantially; these are laboratory observations,
not a statistical confidence interval, an unmodified historical-release
comparison, an Oracle benchmark result or a universal throughput guarantee.
Correctness PRE results are reported separately in the GitHub Release.

Separate instrumented captures showed mean origin residence per matched undo
dependency of 17.28 ms for the control and 0.47 ms for the candidate, with no
trace drops or missing origin intervals. These source-side intervals overlap
client waits and must not be added to client execution time. The extra control
capture had one real remote transaction-proof rejection and is retained as a
failed diagnostic, not an accepted throughput sample. Its exact failed sampling
condition was not captured; this release does not claim that observation has
been independently reproduced and fixed. The candidate capture and formal
correctness qualification remain separate requirements.

## Publication requirements and build identity

Stable publication requires four valid correctness PRE samples on the final
product candidate, zero unexpected client/server errors, no forced cancellation,
complete ordered comparisons of every row on all four nodes, health/invariant
and outstanding-work checks, and coordinated normal shutdown. Original client
exit codes are preserved; natural late completion is accepted only after the
existing full correctness checks succeed. No earlier acceptance lane is silently
reclassified as a new execution on this binary.

The frozen Linux test binary SHA-256 is
`4cbbc0b87505453b6940e207916b8b975ff93e9cdb49373638d49d41f4ba8550`.
It was built with `--enable-cluster --enable-tap-tests --without-icu`, without
`--enable-cassert`; the prefix was an isolated installation. CI separately
exercises assertion-enabled builds. The registered C unit suite contains
312 binaries. Full Fast CI and MVP Nightly CI must execute successfully on the
exact release commit; documentation-only skipped jobs are insufficient.

Release preparation changes version metadata and user documentation, not the
qualified product sources. Keep the source commit, build flags, configuration
and binary hash together. The legacy compiled `pgrac_version()` string is not
the source-release label.

## Installation and limits

Use the [MVP guide](../mvp/v0.131.0/README.md) and
[Linux single-host four-instance Quick Start](../mvp/v0.131.0/quickstart-linux-single-host.md).
Do not hot-replace one node: **all nodes must normally shut down before a
homogeneous binary switch**. Retain the clean original data and use a separate
installation prefix. Unchanged on-disk format does not certify rolling upgrades,
arbitrary cross-version migration or downgrade.

The existing MVP boundaries remain: no certification of independent-host shared
LUN/GFS2 deployment, crash recovery, automatic failover, production external
fencing, backup restore, general data migration, full SQL/2PC compatibility or
production HA. Normal shutdown/restart evidence is not crash-recovery evidence.
Previously published tags, results and limitations remain unchanged.

```sh
git clone --branch v0.131.0 --single-branch \
  https://github.com/sqlrush/pgrac.git pgrac-mvp1
cd pgrac-mvp1
git rev-parse HEAD
cat PGRAC_VERSION
```
